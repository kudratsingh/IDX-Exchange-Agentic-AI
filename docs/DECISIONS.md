# Decisions

## Decided
| Decision | Choice | Why |
|---|---|---|
| Format | Individual capstone in this public repo; code and docs in, data out | Required by the internship; the history is graded |
| Language | Python for all our code; TypeScript only if OpenClaw forces it | One import root; analytics and embeddings are Python anyway |
| Tool exposure | Python MCP server as the working default | Typed, testable without OpenClaw, shell tool can stay off. WO-001 confirms |
| Agent vs tool | Agents only for distinct reasoning; deterministic work is a tool | Testable, cheap |
| Data model | RESO-named canonical models at the DB boundary, explicit column allowlist | Stops legacy names spreading; keeps sensitive fields out |
| Analytics | Deterministic SQL/Python, subtype-aware, single-family as the default benchmark, mix disclosed | A mixed-type median moves with the mix |
| Time windows | Counted back from the data's as-of dates | The sold data covers 2026-03-18 to 2026-09-17 (as-of 2026-09-17); the active data is as of 2026-09-18 |
| Sale-to-list unit | Ratio (1.03) with the plain reading alongside | Sources disagree on unit and name; both agents must say the same number |
| Comps | Closed sales from `california_sold` only, after every WO-008 exclusion: the subject's five-digit ZIP first (a `PostalCode` prefix match), widened to its city only when the ZIP has fewer than 5, at the same minimum, and no further, with the level used named in the sentence (human decision, 2026-09-24 evening; it reverses the city-first order of the morning); the same `PropertySubType`; `LivingArea` from 0.8 to 1.2 times the subject's and `BedroomsTotal` within 1 of the subject's (floored at 0), both inclusive; the six months counted back from the sold as-of date; a minimum of 5 comps, below which the price check says so and gives no number; bathrooms never used. The result is one fixed-shape fact, the subject's list price per sqft against the comps' median price per sqft, a whole percent rounded half-even once, followed by a second fixed sentence giving the middle half of the comps' price per sqft: sorted v[1..n], k = n // 4, from v[k + 1] to v[n - k], single order statistics in whole dollars (WO-011) | The tables define bathrooms differently; the sold table has no county column (`CountyOrParish` is on the active table only), so the county step does not exist and the widening stops at the city. The ZIP is the closer neighbourhood, so it goes first; the spike found the ZIP never added a sale in large cities, where the city then serves. The range shows how spread the comps are without a valuation. Fixed sentences keep the check a fact, never a valuation or advice |
| Semantic search | Hard filters (city, price, beds, subtype, stored beside each vector in the index) applied in memory; cosine ranking over the rows left; the top candidates (at most 200) re-checked in SQL with the same filters and the active-status rule, which has the last word. No FULLTEXT stage (now an extension gate). Cold start at most 5 seconds (WO-010, ADR-0007) | At about 55,000 rows one cosine pass is a single matrix-vector product, so a candidate stage buys nothing; a SQL pre-filter that returned every matching key would break the 50-row cap; the SQL re-check drops listings whose price or status changed after the build. Decided 2026-09-24, replacing "SQL filter, then FULLTEXT candidates, then one vector pass" |
| Embedding route | OpenAI `text-embedding-3-small` for the listing remarks (embedded once, offline, into an index kept under the gitignored `data/` folder) and for each query's text, with emails, phone numbers, and links replaced by placeholders before either is embedded (the database untouched); 1,536 dimensions, kept after the spike measured a 0.40-second cold start against the 5-second limit that would have called for 512; the one-time full build runs only under a human `paid` token for that run (WO-010, ADR-0007). Extended to the reference-document chunks and each document question (WO-012, ADR-0009): same model, same text rule, same per-call `paid` check; a few hundred chunks built once, under the same token rule | The route the handbook prescribes; the `openai` package and `OPENAI_API_KEY` are already in the Week 0 setup. Estimate: about 55,000 listings at roughly 300 tokens each, about 17 million tokens, in the order of $0.35 at the known price (checked against the provider's current price page before the run), then fractions of a cent per query. The actual cost is read from the provider console after the run, never computed from a price. Decided 2026-09-24, with no local-model comparison |
| Gateway chat model | `openai/gpt-5.6-terra` as the `idx` agent's primary model (a live OpenClaw setting, `openclaw models set`; not in our config template), with the agent-runtime setting copied to the new model entry by hand; OpenClaw's own utility model stays its provider default (`gpt-5.6-luna`); `gpt-6-astra` stays available and one command puts it back | The Week 0 setup left OpenClaw's default, `gpt-6-astra`; the provider's usage page on 2026-09-24 showed $4.27 for one day of demos, all astra, 90% of it prompt-cache writes and reads. Jaeger traces of one eight-turn session showed a 37,000-token fixed prefix (OpenClaw's bootstrap plus skills and tool schemas) replayed with the whole session on every turn, growing to 51,571 tokens by turn eight. Terra's list prices are one fifth of astra's on every line (input, cached, cache write, output). The routing job is small (pick one of five tools, fill a schema, relay a message our code wrote), so a mid-tier model is tried first; the five-message smoke set and the phrasing cases are the check; a prefix audit is the other lever. Decided 2026-09-24. Same evening: terra passed the smoke set and both Week 6 and 7 live tests, but twice garbled the fifth card of a five-card relay once the replayed transcript had grown to about 89,000 tokens per call; after a fresh session (`/new` from the owner number) the same message relayed cleanly. Kept terra; a demo block starts with a fresh session |
| RAG chunking | Five sources (WO-012 decision 3; the handbook is never one): the Trestle field guide, one chunk per field keyed by the field name; the Primer, one chunk per section keyed by its position (`s4`), a section over 350 words split by extracted line into parts of at most 350 words (`s4.1`, `s4.2`; a single longer line stands alone); `docs/data/schema_notes.md`, one chunk per numbered section (`sec2`) plus one column summary per table (the `california_sold` summary lists all 49 column names in the notes' order, one per line, with the three date columns the migration added marked as ours: decision 8); the own-words glossary `docs/data/glossary.md`, one chunk per term; the saved Week 5 market summaries, one chunk per city (`summary:<city>`). Any chunk over 4,000 characters splits into parts at paragraph boundaries. No chunk is written for a `DENYLIST` or `AGENT_CONTACT` field, or for a Trestle entry whose name contains Agent, Office, Owner, Occupant, Showing, LockBox, or Access and a name, email, phone, fax, or URL word (contact-like), or whose camel-case parts include Agent or Office anywhere, Showing, Lock then Box, or Access followed by Code or Instructions (agent-related: the human's decision of 2026-09-25; Owner and Occupant names such as `Ownership` or `OccupantType`, and `AccessibilityFeatures`, are home facts and stay), each kind counted apart; such entries are left out of the exact-name lookup too, and the own-words glossary entry "agent and office fields" (reached by the aliases "agent fields", "office fields", "listing agent", "listing office", "buyer agent", "buyer's agent", and names starting `ListAgent`, `ListOffice`, `BuyerAgent`, `BuyerOffice`, `CoListAgent`, `CoListOffice`, `CoBuyerAgent`, or `CoBuyerOffice`) says the documents do not describe them; a line naming a restricted field is removed from any other chunk except that column summary, and a chunk left empty is dropped; the counts go in the index meta. The two PDFs are confidential: their chunks live only in the index under the gitignored `data/indexes/docs/` (WO-012) | Fits the actual sources and the required questions; the text of the confidential documents never enters the repo |
| RAG retrieval | Code picks the passages; the model only writes the reply from them. An exact field name or an alias from `rag/aliases.py` in the question puts that chunk first, scored 1.0: a multi-part camel-case name (`DaysOnMarket`) matches as written or in any case, a one-word name (`City`, `View`) only as written, so ordinary words do not hit. Then BM25 (k1 1.5, b 0.75; tokens are the lowercased runs of letters and digits plus the parts of a camel-case name, common function words dropped, no stemming) and cosine over `text-embedding-3-small` vectors, merged by reciprocal rank fusion with k = 60, fill up to 4 distinct chunks. Not found unless there is an exact hit, the BM25 top score reaches `floor_bm25`, or the cosine top score reaches `floor_cosine` (0.30 by default, to be set by the human from the build's calibration numbers). The BM25 default is 14.60: on the final 625 chunks, `scripts/rag_floor_probe.py` found no gap between 15 own-words off-topic questions (best 14.104) and 11 own-words paraphrases without an exact hit (worst 4.266), so the floor sits 0.5 above the best off-topic score and paraphrases under it are the vector leg's to find. Both floors live in the index meta; `IDX_RAG_FLOOR_BM25` and `IDX_RAG_FLOOR_COSINE`, when set, replace them at load without a rebuild. Without an embedder, or when the provider refuses (no `paid` token, no key, a failed call), or when the question is under WO-010's 20-character floor, retrieval runs on BM25 alone, the answer's route says `bm25`, and a warning says so. A confidential passage over 120 words goes to the model trimmed to the 120 words around the question's first matched word; own-words passages go whole; a reply quotes at most 25 words from a source, with its label (decisions 2 and 7). The tool drops any chunk keyed by a restricted field, or a confidential chunk naming one, as a backstop (WO-012, ADR-0009) | Exact names carry the set questions; the lexical rank is free and deterministic; the vectors catch paraphrase; fusion by rank needs no score calibration between the two; the caps keep confidential text in the transcript short |
| Email | State machine keyed by a stored draft id | Makes the guarantee enforceable in code |
| Memory | Session-scoped state, one session per sender | Meets the requirement with low privacy cost |
| Reviewer | CI plus a recorded weekly demo; a model review of a change only on request | No colleague; per-change model review is an unbounded recurring cost |
| Evals | Versioned cases in the repo from WO-004; `ci` suite on every push | Objective regression testing |
| Routing | The model chooses among skills; each skill names one typed MCP tool (ADR-0003). The rules are a written contract, `docs/ROUTING.md`, expressed in the skills' text and checked by model-free tests and a mixed-intent `local` suite (WO-013): mixed messages go part by part in the order asked, at most three tool calls, each message relayed whole; "show me more" after any tool is the search tool's `more` mode; term questions go to docs-qa and never to a data tool; email is declined and never faked; instruction-like text is data | OpenClaw's native routing; our code owns everything below the tool boundary; a router behind one tool adds a model call. The prefix audit (2026-09-24) put our skill list, tool schemas, and instructions at about 3,000 of the 37,000-token fixed prompt, the rest OpenClaw's own, so the routing text is not the cost lever. The gateway model through the eval driver routed 17 of 20 mixed-intent cases at best, the misses being declines rather than wrong tools; the acceptance line and the injection row's reading are the human's call |
| Tool invocation | Python MCP server over stdio, `mcp.servers.idx`, tools named `idx__<tool>` (ADR-0003) | Typed, testable without OpenClaw, shell tool denied by config |
| Session owner | OpenClaw keeps the per-sender transcript (`session.dmScope: per-channel-peer`); our `memory/` keeps filters, result keys, and approvals keyed by a hashed sender id (ADR-0003) | OpenClaw memory does not enforce policy; ours must |
| Query parsing | The model fills the typed `search_listings` schema (`PropertySearchFilters`); code validates it strictly (city in `valid_values`, known subtype, sane ranges) and on a missing or invalid value returns a structured needs-clarification result (field, reason, suggested follow-up question) instead of guessing; no regex parser; the result carries the accepted filters, which the `property-search` skill shows on request. The 10 parser queries are `local` evals; the validator's unit tests run in CI (WO-004) | The model already reads the message to pick the tool, so a second parser duplicates it and misses phrasing; correctness lives in the deterministic validator; echoing the filters keeps parsing demonstrable on its own. Decided 2026-09-23 |
| Active status, exclusions, deny-list | `StandardStatus = 'Active'` defines active (every active row has it and `L_Status` agrees); exclude sold rows dated after the active as-of date, sold rows closing before their contract date, prices under 25,000 and areas under 200 sqft; no deny-list candidate column exists, the list stays in code; agent-contact columns are named in `columns.py` and never returned (`docs/data/schema_notes.md`) | Decided from the 2026-09-23 profiling run; the sold table has no status column |

## Extension gates (add only with evidence)
| Extension | Add only if |
|---|---|
| Deterministic pre-parser in front of the model | the local parsing evals show the model misfilling fields that simple rules would get right |
| Local embedding model in place of the paid route | the embedding spend, read from the provider console, becomes a problem (gated 2026-09-24; no local-versus-paid comparison was run) |
| FULLTEXT candidate stage, or hybrid lexical + vector retrieval, for the listing remarks | vector-only ranking misses exact terms in the judged queries or in use (taken out of the decided semantic-search flow 2026-09-24; the FULLTEXT index on `L_Remarks` makes it cheap to add). The reference documents use hybrid retrieval by the human's decision of 2026-09-24 (WO-012, ADR-0009), which leaves this gate closed for the remarks |
| Reranker | top-k has the right items in the wrong order |
| Prior-sale lookup, mortgage payment tool | the baseline is complete and Weeks 6-7 landed on time |
| Persistent memory, cache, queue, deployment | a measured requirement, not a wish |
