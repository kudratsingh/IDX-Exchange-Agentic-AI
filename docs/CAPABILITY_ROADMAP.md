## Remaining proposed capabilities

Compound-request planning with progress and payload verification; selective schema
loading; comparison matrices with explicit user priorities and ranking sensitivity;
travel-time/amenity search and maps; photo-based search; per-user transaction-document
ingestion; voice input/output; operator handoff with a structured brief and showing
integration; personalized market reports; feedback-based ranking; interactive
refinement and private shortlist pages. These are backlog items, not available tools.

Cloud API/interactive media, geospatial services, document storage, new model calls,
training and photo embeddings each need their own architecture/privacy/budget decision.
Do not infer event freshness from the current snapshot, prediction accuracy from a
training score, or public availability from a local demo. Housing-budget estimates
must show assumptions. Place searches use distances to destinations, never demographic
steering or school-quality rankings. The current email approval chain remains intact.

## Finish the current handoff

WO-015 operator-command hook classification needs the human's separate gates grant.
Then select the chat provider and retain compatible embeddings; run consented live
acceptance, the operator-approved delivery, relevance judging, and the final recording
and reflection. Optional alert scheduling follows rehearsal. New-feature implementation
must not rewrite these as completed or require a public portfolio launch.
